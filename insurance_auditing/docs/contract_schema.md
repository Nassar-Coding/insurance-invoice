# Declarative record specification v2

Finite data records describe hospital/contract identity, term, service-day and exclusion interpretation, reviewed source hashes, explicit review state, service names and IDs, unit basis, versioned rates with priority, daily thresholds/caps, weekend multipliers, volume thresholds, facility/tier multipliers, bundle substitutions and exclusions. References identify controlling clauses. Rate/threshold/multiplier values are integers or integer ratios; no floating money or executable expressions exist.

The fixed interpreter supports: service-date version precedence; calendar grouping; exact half-up per adjustment; bundle → facility → tier → premium/uplift → deepest strict-prior volume discount → billed quantity; caps where the invoice amount can be established; unit, arithmetic and contract-reference checks; exclusion applicability; duplicate/unknown-fact abstention. Unsupported composite measurements and ambiguous temporal/directional cases stay explicit. Additional source-supported operations require a versioned interpreter/schema change and affected regression evidence.

A bundle binds accepted contract/mapping/lexicon bytes to source hashes and the compatible schema/semantics versions. Runtime validates before pricing. Source review is required in addition to structural validation. Base/amendment overlap is authorized only with explicit precedence and distinct priority; conflicting equal-priority intervals are rejected. Changing invoice data creates a different run identity without automatically invalidating unchanged reviewed contract extraction.

Schema and semantics version 2 make invoice effectiveness and service-date-after-invoice restrictions explicitly contract-specific. H2 has no imported duplicate-day or invoice-date prohibition; its missing actual submission/waiver facts block complete opinions. Calendar Service Day is used only where supplied terms support it. H2's 07:00 day is unobserved and bounded conservatively; H4 utilisation has a patient-scope envelope. H5's adopted invoice-facility projection is an explicit outcome-relevant qualification. See the complete versioned enum set in `schema.py`.

Mapping normalizer version 2 performs Unicode/case/spacing/punctuation handling and strips only a terminal opaque identifier of the form `/NG-123`, `/RM-123`, `/SA-123`, `/CW-123` or `/PH-123`. Raw text remains available and its normalized value must match its stored key. A frozen key resolves only through reviewed records. Abbreviations/candidate generation are acquisition aids, not runtime semantic matching. Missing essential qualifiers cannot be supplied by catalog uniqueness or billed price. Elision of a generic final noun has a distinct evidence grade. Unknown candidates retain all plausible services (or unrestricted uncertainty when none is established), so they cannot silently disappear from history.
